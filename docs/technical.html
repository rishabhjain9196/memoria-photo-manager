Technical document

How Memoria is built: architecture, modules, data model, algorithms, the journaled executor that makes every file operations recoverable, concurrency, performance, testing and packaging.

Python 3.11+PySide6 6.7+SQLite schema 6 · WAL NumPy · Pillow · OpenCV 4 · FFmpegUnreleased updates after 1.4

Overview

Memoria is a two-layer application:

  • memoria.engine — a UI-independent library. Every operation is a plain function taking a Library and an optional Progress. It is fully testable without Qt.
  • memoria.ui — a PySide6 shell: a main window with sidebar navigation, one page per tool, a single background TaskRunner, and shared widgets.

File plans use Action lists and actions.apply. Exporters use actions.created_batch and shared publish_file/record_output to journal each output before publication. Selective catalogue reset has a separate durable state machine; metadata deletion is not Undo.

Architecture

Dependencies point downward only: pages import engine modules; the engine never imports Qt. The AppContext object carries shared state (open Library, runner, thumbnail cache) and app-wide signals (library_opened, library_modified, toast_requested, navigate, browse_requested, album_requested). The diagram shows the main file-operation path; Insights uses read-only background queries and reset uses its own journaled phases.

Schema versioning

PRAGMA user_version records the schema version. The v1 schema is frozen; later changes are numbered steps in db.MIGRATIONS, applied in transactions on open. A catalogue with a higher version than the app raises LibraryTooNew rather than being misread. Current version: 7. Back up the catalogue before upgrading if you need to return to an older application build.

Version 6 adds the metadata fields and defaults metadata_version to 0. Scanner analysis includes media with an older/missing marker even when analyzed=1; each completed batch stores the new fields and current marker. Cancelled refreshes resume incrementally. Legacy parked/missing snapshots inherit default 0 when restored. IDs, relationships and health baselines are not reset. Invalid optional EXIF numbers are logged and left NULL.

Version 7 adds duplicate_kept, containing signatures of unchanged Keep both/all review groups. It does not change the media-analysis version. Signatures cover group identity and reviewed file IDs, paths, sizes, modified times and hashes. Saved decisions stay local to the catalogue and are not exported in diagnostics.

Pipelines

Indexing (scanner.scan + scanner.analyze)

  1. Walk with an explicit stack over os.scandir, skipping .memoria, $RECYCLE.BIN, System Volume Information; never follows links.
  2. Diff against the catalogue by lower-cased relative path: new rows inserted; rows whose size or mtime changed have derived columns reset (analyzed=0); genuinely missing rows move to missing_files without deleting thumbnails. Failed file stats retain entries. Returning paths restore identities before updates.
  3. Analyse un-analysed media in a ThreadPoolExecutor (images: WORKERS threads; videos: a smaller pool), with at most 2 × (image workers + video workers) submitted jobs. Per image: open → draft() JPEG decode near 512 px → EXIF → transpose → resize to exactly 512 px on the long side → dHash, Laplacian-variance sharpness, brightness, contrast, clipped share → 256 px thumbnail. Per video: probe + one frame at min(1 s, duration/2).
  4. Date resolution: EXIF DateTimeOriginal → DateTimeDigitized → DateTime → video creation_time → regex on file name → file mtime (modified).
  5. Commit every 200 results or approximately one second, including when waiting for a slow remaining future, so completed work becomes available and cancelled runs keep committed progress.

Errors (truncated, unidentified, no video stream) are stored per file and never abort the run.

Exact duplicates (duplicates.confirm_identical)

media files ──group by size──► sizes with ≥2 files ──quick_hash (5×64 KiB + size)──►
groups with equal (size, qhash) ──full_hash (xxh3-128 of whole file)──► identical groups

Hashes are computed in parallel and cached in qhash/chash. The keeper is the minimum of keeper_score = (penalty, mtime, path length, path) where penalty = 3 for a copy-like name ((1), copy, _copy, duplicate, ~1) + 2 for a copy-like folder (backup, download, whatsapp, temp, export…) + 0.1 per folder level. plan_removal emits recycle actions with hash = group hash (forces a fresh full hash of each copy) and a guard = (keeper path, hash) verified once per batch. Explicit selected file IDs can instead remove one chosen copy or all shown copies; a survivor guard is omitted only when no shown member is being kept. Source hashes/stat checks remain.

Duplicate folders (duplicates.find_all, find_duplicate_folders, plan_cleanup)

  1. One funnel: find_all runs confirm_identical once over every non-junk, non-empty file (media and documents) and derives the media groups shown as single files from it.
  2. Folder contents: every folder (with its sub-folders) accumulates a FolderInfo (files, photos, videos, others, their bytes, sub-folders) and a multiset of content hashes. Junk and 0-byte files count towards sizes but not contents. A folder holding any file with no copy anywhere cannot be a duplicate.
  3. Top folders: a parent holding exactly what its child holds (nothing else) is the same folder; chains collapse to the highest one.
  4. same: top folders with equal multisets (never nested). inside: for each top folder, the ancestors of each copy of its rarest content are walked upwards; the first folder whose multiset contains it is a container. Originals win over backup/download-looking folders, then fewer files.
  5. Highest level only: a match is dropped when a parent of the folder is already a duplicate of a folder that holds the other side (e.g. Old Laptop\Pictures\Family 2020\Picnic ≡ Albums\Family 2020\Picnic is implied by Old Laptop ≡ Albums). Matches are ordered shallow-first so one representative of a collapsed set survives when a third copy exists elsewhere.
  6. Single files: DuplicateReport.loose_groups(keepers) removes copies inside folders being removed; groups that fall below two copies disappear (their copies are handled with the folder).
  7. Plan: plan_cleanup takes the outermost folders to remove, then for each file finds an identical copy that stays (outside every removed folder and not removed by the file plan; best keeper_score). A folder with any file lacking such a copy is dropped and the check repeats. Files get recycle actions guarded by that copy (junk and 0-byte files go along unguarded); folders get rmdir actions deepest-first, which pre-flight skips unless the folder is empty.

Explicit folder choices are limited to members of the reviewed match. inside matches never permit removing the containing folder. Removing all same folders intentionally has no survivor requirement; it uses minimal file snapshots captured during Find, including fingerprints for empty/junk entries. Unverified snapshots reject the plan; newly added files cannot be included. The ordinary folder planner excludes all other planned removals from potential survivor guards and respects explicitly protected keep choices.

Folders with explicit review choices are accounted for before rebuilding loose file groups, avoiding overlapping individual plans. The UI stages selections before one shared confirmation, with a mandatory acknowledgement for Remove both/all. Only Keep decisions persist; Include all and later scans never replay prior Remove-all choices.

Cost is O(files × folder depth) in memory after hashing: ≈0.1 s for the sample library with cached hashes.

Similarity & best shot (similar)

  1. Hash pairs: 64-bit dHashes as uint64; for each 512-row block, XOR against 8,192-column tiles and np.bitwise_count (≈32 MB per tile). Blocks run on a thread pool (NumPy releases the GIL). Pairs with distance ≤ threshold (10) are unioned (disjoint-set).
  2. Bursts: capture times from EXIF/video metadata only (file-name dates are too coarse) are sorted; a sliding window joins pairs ≤ 3 s apart with distance ≤ 16.
  3. Collapse identical: members are passed through confirm_identical; byte-identical files keep one representative (they belong to Duplicates). Groups that fall to one member are dropped.
  4. Faces: computed lazily for group members only (OpenCV Haar, 640 px, thread-local classifier) and cached.
  5. Rank: score = 0.55·log1p(sharp)/log1p(max_sharp) + 0.25·exposure + 0.08·pixels/max_pixels (+ 0.12·faces/max_faces), where exposure = 1 − min(1, 2.5·clipped + 0.6·|brightness−118|/118). Reasons are generated from the same quantities.
  6. Burst flag: ≥3 members, all with capture times, spanning ≤ 3 s × members.

Blurry: sharpness < threshold with presets strict 8 / normal 20 / lenient 45 (variance of the Laplacian at 512 px).

Matching pairs are streamed without retaining a Python set of every edge; the burst pass checks whether a pair was already covered by its distance. Pair comparison remains quadratic, and dense block outputs can still be large.

Organise (organize.plan_organize)

Eligible rows: media with a date, no error, size > 0, not AppleDouble. Rows dated only by modified are counted as skipped unless include_uncertain. Destination = pattern folder + original name; clashes with existing or already-planned names (case-insensitive) get " (n)". empty_folders_after walks every source folder's ancestors and returns those whose remaining file count (existing non-moving files + incoming destinations) is zero, deepest first, to append as rmdir actions.

Tidy (tidy.find_tidy)

Classifies catalogue rows: junk (names/extensions/._ prefix) → empty (0 bytes) → unreadable (media with error) → other (non-media). Empty folders are computed from a recursive per-folder count that excludes files about to be removed, so folders containing only junk qualify. Plans recycle files first, then rmdir deepest-first.

Health (health.run_health)

Runs an incremental scan, then re-reads every file (thread pool, half the workers to be gentle on HDDs) computing the full hash and, for images, a reduced-size decode. Classification against the stored fingerprint: none → new; size+mtime equal and hash equal → ok, hash differs → damaged; size or mtime differ → edited; decode failure → unreadable. Fingerprints are refreshed except for damaged files, which stay flagged.

Missing-file results come from durable missing_files, not just the current scan's removal count. The edited label is a size/mtime heuristic, not evidence that a change was intentional.

Compare & sync (compare)

Refuses overlapping folders. Lists the other folder without writing to it, then hashes only files whose size occurs on both sides (library hashes cached, other side hashed in memory). Results: only-here, only-there, in-both counts. plan_sync emits copy actions preserving relative paths; the executor's verified copy never overwrites (clashes get a new name). Traversal/stat/required-hash failures abort comparison explicitly instead of returning a misleading empty or incomplete backup inventory.

Video compression (videotools)

  • Output size: limit applied to the shorter side (portrait-safe), even dimensions, Lanczos scaling.
  • Quality mode: libx264 CRF 20 / 24 / 28 (high / balanced / small), preset medium, AAC ≤ 128 kbps (never above the source), -map_metadata 0 -movflags +faststart.
  • Target mode: two-pass ABR; video kbps = target × 97% payload / duration − audio; audio drops to 64 kbps when video would be < 400 kbps; floor 150 kbps (flagged infeasible with an explanation).
  • Progress: -progress pipe:1 parsing of out_time_us; pass 1 = first half.
  • Verification: output must probe, match duration within max(0.5 s, 2%), and be smaller — else discarded. Optional SSIM via FFmpeg's ssim filter over ≤ 600 sampled frames, source scaled to output size.
  • Publishing: work in .memoria-work-* inside the output folder, rename to a unique <stem> (compressed).mp4, copy source mtime. Cancellation kills FFmpeg and removes the work folder.

Estimates (no encoding): quality mode uses bits-per-pixel 0.09 / 0.055 / 0.032 × w × h × fps, capped at 90% of the source video bitrate.

Story rendering (story)

  • Sizes: story 1080×1920, post 1080×1350, square 1080×1080. Photos loaded upright at ≤ 2,200 px.
  • Templates: single, duo, trio, grid4, before_after, polaroid (slots 1/2/3/4/2/1). Backgrounds: blurred darkened cover, black, white or hex colour. Fit: contain, or cover with a centre-weighted edge-energy saliency focus.
  • Captions: Segoe UI fonts, word-wrapped, on a translucent pill with shadow.
  • Panorama carousel: N = round(aspect / 0.8) slides (2–10) cut from one continuous scaled strip, so edges match.
  • Story video: each photo pre-composed once (8% oversize for Ken Burns), per-frame zoom/pan via cv2.warpAffine, crossfades via cv2.addWeighted, raw RGB piped to FFmpeg (libx264 CRF 20, BT.709) by a writer thread with a 4-frame queue. Duration = n·spp − (n−1)·transition. Optional music with a 1 s fade.
  • Exports are all-or-nothing: on cancel, files written in that run are removed.

Similar videos (videosim)

  • Signature: 8 frames at 5 %…95 % of the duration from one FFmpeg call per video (short clips decoded straight through, longer ones seek per frame; per-frame fallback), each reduced to a 64-bit dHash. Near-blank frames are ignored so black/white screens don't match each other.
  • Match: durations within max(1 s, 4 %) and median frame Hamming distance ≤ 12, trying offsets 0 and ±1 frame to tolerate small trims. Measured: copies 3–9 (two different trims of one video up to 15, still grouped through the original); unrelated clips ≥ 16.
  • Groups: union-find, byte-identical copies collapsed (they belong to Duplicates), best pick by pixels (>5 %), then bitrate (>15 %), then duration (>0.25 s), then duplicates.keeper_score.
  • Cost: ≈0.13–0.16 s for a 4 s 720p clip, ≈0.4 s for 20 s, ≤1 s for 60 s; cached afterwards.

Check everything & batch actions

checkup.run calls scanner.index, duplicates.find_all, similar.find_similar, videosim.find_similar_videos, similar.find_blurry, tidy.find_tidy and organize.plan_organize, each with a StepProgress. The UI stores the results in AppContext tagged with the library generation; pages use them only while the generation is unchanged (any library_modified bumps it), and sidebar badges are cleared at the same moment.

batch builds ordinary Action lists from a selection in Photos & videos, so batch operations get exactly the same pre-flight checks, journal, verified copies and undo as every other tool.

Editor (photoedit, videoedit)

Each file in the Editor has its own recipe (PhotoEdit or VideoEdit), a plain dataclass. Nothing touches the source until Save; outputs are always new files named "name (edited).ext" (made unique, never overwriting). Workers open actions.created_batch; shared publication persists each fingerprint and pending record before renaming. Completed items remain in History if a later item is cancelled. Undo requires a matching recorded hash.

Photo pipeline

open (EXIF-oriented) → rotate 90° steps → flip H/V → straighten (rotate + largest inner crop, no empty corners)
→ crop (normalised box on the transformed image) → auto enhance (autocontrast, 0.5 % cut-off)
→ brightness / contrast → saturation → warmth (R/G/B tone curves) → filter → sharpen → resize (never upscale)
→ save: same format (HEIC/RAW → JPEG), quality, EXIF kept with Orientation=1, GPS optionally removed, mtime = source

Previews run the same pipeline on a 1,600 px copy in a latest-wins BackgroundCall with a 140 ms debounce, so the slider position you see is the pixels you get. Split cuts a grid of exact pixel tiles; Join stacks images horizontally or vertically, scaled to a common height/width and capped at MAX_JOIN_SIDE.

Video pipeline

ffmpeg -ss start -t length -i src                       (input seeking, frame-accurate with re-encode)
  -vf  transpose / hflip,vflip → crop=w:h:x:y → eq=brightness:contrast:saturation
       → scale=W:H (max height, even dims, lanczos) → setsar=1 → setpts=(PTS-STARTPTS)/speed
  -af  atempo chain (each factor 0.5–2.0) for speed  |  -an to mute
  -c:v libx264 -preset medium -crf (quality) -pix_fmt yuv420p  -c:a aac  -movflags +faststart
  → temp file → verify duration → publish under a unique name

Cuts are frame-accurate because every export re-encodes. Display-rotated sources are baked upright, and any output that still carries a rotation flag is rejected. split exports consecutive ranges; join normalises every clip to the first one's size (letterboxed), 30 fps and AAC, adding silence for clips without audio. Each output's duration is checked against output_duration. Incomplete work files are cleaned up; completed outputs in a batch may remain and are recorded by the publication journal.

People (faces)

  1. Models: YuNet (face_detection_yunet_2023mar.onnx, 0.2 MB, MIT) finds faces and five landmarks; SFace (face_recognition_sface_2021dec.onnx, 37 MB, Apache 2.0) aligns each face to 112×112 and outputs 128 numbers. Both run through cv2.FaceDetectorYN/cv2.FaceRecognizerSF; the ONNX bytes are read by Python and passed as buffers so any install path works. One model pair per worker thread.
  2. Detection: the photo is decoded upright at ≤ 1600 px and searched twice — at 640 px (YuNet is trained on faces of about 10–300 px, so large portrait faces need a smaller image) and at full 1600 px (small faces in group photos). Overlaps are merged (keep the most confident when they share > 40 % of the smaller box); faces scoring < 0.8 or smaller than 20 px are dropped.
  3. Scan: photos whose (size, mtime) differ from face_scans are processed in chunks of 48 on a thread pool with cv2.setNumThreads(1) (parallel across photos rather than inside each model); each chunk is committed, so cancelling keeps finished work. Faces of files gone for good are removed; files in Recovery keep theirs for Undo, and missing records retain theirs until explicitly forgotten.
  4. Grouping (cluster): unconfirmed matches are cleared; each free face joins the named person whose confirmed-face centre is most similar (cosine ≥ SAME_PERSON = 0.42) unless a reject exists; the rest go through group_faces: a leader pass in order of detection quality, merge rounds of group centres (best pairs first, each group once per round), and a final reassignment of every face to its closest centre.
  5. Calibration: on the public-domain test portraits, same-person similarities were 0.34 or more and different-person ≤ 0.32 (excluding two deliberately hard photos, which stay apart instead of merging wrongly).

Cost: ≈0.16 s per photo on one core (two detections + one signature per face); the full sample library (127 photos, some 12-megapixel) takes ≈5 s on a 32-thread PC. A re-run with nothing new takes milliseconds; grouping 15 faces takes ≈1 ms.

Albums & places (albums, places)

  • Candidates: photos and videos with a reliable date (camera, video metadata or file name — not file modified time), excluding screenshots and damaged files; exact duplicates are reduced to one copy with duplicates.confirm_identical + keeper_score.
  • Events: sorted by time; a gap > gap_hours (8) starts a new album unless the new photo and the album's last known place are within place_km (40 km) and the gap is ≤ trip_days (3). Albums with fewer than min_items (3) are dropped. Name: the most common place label, if at least a third of the items have a location, then date_range.
  • Places: places.nearest finds the closest of 34,197 towns (haversine over NumPy arrays, ≈1 ms; lookups cached per 0.01°), then picks the most populous within 12 km of it. Labels: "Town, Region" within 8 km, otherwise the region ("Goa"); nothing beyond 75 km.
  • People: one album per named person from faces.photos_of.
  • Export: plan_export emits copy actions into dest\<folder_name(album)> (Windows-safe, unique per export); the executor verifies each copy and never overwrites. Undo removes copies that are unchanged; the album folders stay.

Action executor & journal

actions.apply(lib, kind, title, actions, progress) executes reviewed move/copy/recycle plans. Generated outputs use the companion publication journal.

for each Action (in order):
    preflight ── guards (keeper exists + full hash, verified once per batch)
              ── src exists / folder empty (rmdir)
              ── size == reviewed size, mtime == reviewed mtime
              ── full_hash(src) == expected (recycle/move with hash)
    fail?  → journal 'skipped' + reason, continue
    dst   = recycle: recovery/<batch>/<rel path>   move/copy: requested path
            made unique ("name (2).ext") — never overwrite
    journal 'pending'
    perform: recycle/move → safe_move (rename on same volume; else verified copy + remove)
             copy         → verified_copy (tmp → hash compare → rename)
             rmdir        → os.rmdir (only if empty)
    update catalogue for this operation (park recycle; rewrite moved paths)
    journal 'done' | 'failed' + error (completed moves awaiting catalogue repair remain pending)
batch status = applied | partial | nothing

Undo

Processes done operations in reverse. Moves are reversed with safe_move; if the original path is taken the file is restored as a unique name and reported. Copies and published outputs (op="create") are removed only if a recorded full hash exists and still matches; their catalogue rows are dropped. rmdir is reversed with mkdir. The batch becomes undone or partial; empty recovery sub-folders are pruned. The UI re-indexes afterwards.

Crash reconciliation

reconcile(lib) inspects pending operations and done operations in interrupted applying batches. Move/recycle completion requires the destination to exist and source to be absent; copy/create completion requires the recorded destination hash to match. Catalogue parking/moved paths and batch totals are reconciled too. Stray copy .memoria-tmp files are removed. Applying batches become partial. This does not repair arbitrary disk or SQLite corruption.

Recovery

recovery_size walks the folder; empty_recovery(lib, batch_ids=None) deletes batch folders, marks their recycle operations purged and batches emptied after successful removal. Errors propagate and preserve remaining recovery records. Undo and exporter rollback can separately delete generated copies.

Catalogue queries and offline maps

catalogue.Filters is shared by Photos, Insights and chart navigation. Values are SQL parameters; sort expressions come from a fixed whitelist. Folder matching has a separator boundary, so Trip does not match Trip2. Person/face predicates use EXISTS, preventing duplicate rows for multiple faces in a file.

  • page returns at most 500 rows plus matching count/bytes. Sorting has path/ID tie-breakers. Ctrl+A and batch actions are page-scoped.
  • Metadata sorts use NULL-last guards and numeric expressions: megapixels = width × height / 10⁶; overall estimated Mbps = size × 8.0 / duration / 10⁶ for positive-duration videos. Zero/unknown duration is never divided by. Video-only and photo-EXIF ranges exclude inapplicable rows, while unconstrained missing metadata remains visible.
  • Storage aggregates exact indexed folders, then rolls up immediate children once per file; format counts use SQL GROUP BY.
  • Calendar periods use inclusive starts/exclusive ends, including leap days. Inclusive UI range endpoints convert to an exclusive next day. Album links count only matching members.
  • GPS must be in legal latitude/longitude ranges. Auto uses approximate Natural Earth India polygons, otherwise the world. A 64×40 grid (up to 65×41 endpoint bins) bounds marker/list rows; each marker carries actual coordinate minima/maxima for exact browse-through filtering.
  • geography.countries caches 177 public-domain country outlines. QPainter draws locally; no WebEngine, online tiles or new runtime dependency is used. Vector paths are built once and transformed/clipped per frame.
  • Insights coalesces rapid requests, rejects stale generation/filter results and closes worker connections. Viewport-only requests reuse storage/timeline/album results. Zoom/pan immediately redraw the map without disabling it; obsolete viewport results cannot snap it back. Accessible named location lists complement photo-marker clicks.
  • places.map_labels reuses the bundled GeoNames table: population-prioritised country, region/city or town candidates according to viewport width. At most 160 candidates and 60 non-overlapping on-map labels; region names are anchored at settlements, not invented state centres. Nearby cluster names use the existing distance/population ranking, with a safe latitude prefilter to reduce repeated distance calculations.
  • Wheel angle and pixel-only touchpad deltas support fractional steps; zero motion is ignored. Buttons and keyboard +/− zoom, drag/arrow keys pan. Bounds are clamped to the world and minimum span; a drag never selects a marker. No state boundary polygons, street tiles, address lookup or POI service is added.

Selective storage reset

storage.reset validates selections/free space, reconciles file operations, then clears selected catalogue fields and records storage_reset in one transaction. Parked/missing JSON snapshots receive the same selected field clearing, so Undo cannot resurrect deliberately discarded health/analysis data.

atomic selected-data clear + pending marker
    → caches (thumbnail database transaction; safe to retry)
    → compact (optional VACUUM + WAL checkpoint; can be skipped)
    → rebuild (incremental scanner.index; committed analysis retained)
    → remove pending marker

Compaction conservatively requires twice the larger database's page allocation plus 16 MiB free, allowing for a temporary database and WAL. Personal metadata clearing is not undoable. Reset retains file IDs, operations/batches, media, exports and Recovery. Maintenance state gates other library actions until completion; page-local caches and selections are discarded. Reset does not delete .memoria or recover an unreadable SQLite database.

UI architecture

  • Page lifecycle: pages listen to library_opened/library_modified, mark themselves stale and normally refresh when visible and the runner is idle. Photos also refreshes committed rows during read-only indexing as described below. refresh() does cheap catalogue reads; expensive work goes through run().
  • Live index view: AppContext tracks normal read-only indexing separately. Photos opts into live refresh; other pages are disabled. A two-second timer emits index-specific updates without invalidating diagnostics or launching other finders. Photos queries analyzed=1 (not metadata-version readiness), holds active selections/scroll/later pages, and invalidates only refreshed rows' pixmaps. Final notifications run after worker callbacks; close/library-change guards reject obsolete completion callbacks. Maintenance resets remain gated.
  • Shared change flow: Page.apply_actions → ConfirmDialog → runner.run(apply [+ index]) → library_modified → toast with Undo (batch id) → failure dialog if needed.
  • PhotoGrid: QListView (icon mode, uniform sizes, batched layout) + PhotoModel holding plain dicts + PhotoDelegate custom painting (rounded thumbnail, badge, tick box, video tag, captions). Thumbnails load on demand through a byte-budgeted ThumbCache, invalidated on library changes. Photos loads at most 500 rows.
  • Preview: full image decoded at 900 px via media.load_for_display (draft decode keeps it fast).
  • Styling: one Qt stylesheet (theme.QSS) using object names (primary, danger, card, tile, trust…); Fusion style for consistent rendering.
  • Lazy pages: only Overview is built at start; other pages are created on first visit.
  • Themes: theme.use(mode) sets the palette, stylesheet and QPalette; changing theme builds a new window and reopens the same library and page (no stale colours). "Match Windows" follows styleHints().colorSchemeChanged.
  • Insights: Overview computes card texts with BackgroundCall (own SQLite connection, closed with close_thread), showing "Updating…". Library insights uses its own coalesced worker queries.
  • Persistence: theme.settings() → QSettings("Memoria", profile) stores theme, window geometry, last library and page, recent libraries. Tests and tools set MEMORIA_PROFILE so they never touch the user's settings.

Opt-in aggregate diagnostics

engine.diagnostics reads a SQLite transaction snapshot using aggregate queries; no media analysis or file-content reads are requested. Unknown formats/codecs/statuses are grouped into fixed categories in SQL before reaching the report. Camera, lens, names, paths, GPS coordinates, capture dates, hashes and face vectors are never selected for export. Error messages are reduced to a fixed category, not scrubbed and copied.

Metrics retains bounded per-operation counters, total/mean/max wall time and process-CPU deltas. TaskRunner emits only fixed operation keys/outcomes and numbers, never task titles or traceback text. Browse-page, preview and Insights scopes use the same collector. Windows process-memory counters provide working set and lifetime peak for the app process only; unavailable counters are explicit. CPU deltas can include concurrent app work.

ui.diagnostics.DiagnosticsController keeps consent in per-device QSettings for each library. It coalesces updates, periodically captures an in-progress main task and uses one background report worker. Each recording session/library has a random report filename under the source checkout's diagnostics/reports folder. No hostname, username, drive letter/serial, absolute activity timestamp or personal identifier is exported.

Publication writes a temporary JSON file, flushes/fsyncs, checks the opt-in generation under a lock, and atomically replaces the session report. Opt-out/library changes invalidate pending publication. Failures are surfaced without writing raw exception strings into diagnostics. Normal close flushes a final aggregate; abrupt termination retains the previous snapshot. Temporary staging files are gitignored; reports require manual review/staging/push.

Cached catalogues work immediately, but old unrecorded timings cannot be inferred. Reports can be incomplete during indexing, unavailable on a disconnected catalogue, and are not guaranteed anonymous. Packaged installations without a source checkout cannot use repository-local recording. No network service, dependency or schema migration is added.

Main-task completion/catalogue changes request a snapshot; heartbeat/manual/close snapshots include browsing and preview timings accumulated in memory. Individual browse clicks do not trigger repeated whole-catalogue aggregation.

Key-event notifications

ui.notifications.NotificationManager consumes AppContext.notification_requested(str, int) on the UI thread. Only registered event keys and nonnegative counts are accepted; fixed templates, not task titles or error bodies, reach QSystemTrayIcon.showMessage. No network service, dependency or schema change is needed.

Background-only delivery uses application activation plus the main window's minimised state, so a focused viewer or modal dialog does not accidentally count as background. QSettings stores delivery mode and selected categories. The in-memory list retains at most 50 enabled events, resets with a library/window change, and is not included in diagnostic reports. Missing tray/message support retains the list; offscreen platforms never create a native tray.

Index/rebuild success is emitted from the result callback, not a progress percentage. Common read-only Page tasks emit results-ready; result-aware callers disable that default and classify batch failures/skips, handled cancellation, editor failures, compression refusals and health findings. MainWindow handles worker failure/cancellation, avoiding a second paused event on rebuild failure. Messages do not overwrite Undo toasts. Tray clicks only restore the current window/dialog because Qt's message-click signal has no event ID. Close disarms delivery before cancelling/draining workers.

Techniques

  • JPEG DCT-domain downscaling via Image.draft; Pillow, NumPy and xxhash release the GIL so threads scale.
  • Batched transactions (200 rows), WAL, FULL catalogue durability and NORMAL cache durability; 32 MiB page cache per connection, separate thumbnail DB.
  • Size-first duplicate funnel and cached hashes; compare hashes only cross-side size collisions.
  • Tiled similarity remains O(n²); dense block results can be large. The burst window can also be quadratic when many timestamps coincide.
  • Photos uses 500-row pages; thumbnail pixels have a 64 MiB cache budget plus Qt overhead. Other pages can still load whole groups.

The current report uses small generated media and synthetic 10,000-entry catalogues representing 300 GB. It does not establish real-drive throughput at that size. Face-centre merging remains a dense-matrix scaling limit.

Extending Memoria

Adding a tool that changes files

  1. Engine: write a find_* function (read-only, accepts progress) and a plan_* function returning list[Action]. Set size/mtime (and hash/guards when identity matters) so pre-flight can detect stale reviews. Use op="recycle" for removals.
  2. Add ground-truth scenarios to samplelib.build and assertions to tests/test_engine.py, including apply → undo restores the tree.
  3. UI: subclass pages.base.Page, set title/subtitle, implement refresh() and on_busy_changed(), run finds through self.run(), and apply through self.apply_actions(kind, title, actions, summary=…, details=…, confirm_text=…, note=recovery_note(), done_message=…).
  4. Register the page in main_window.NAV and page_classes, add a card to Overview, and extend tools/ui_screenshots.py so the smoke test drives it.
  5. Tools that create files must wrap work in actions.created_batch and publish through videotools.publish_file. record_output persists intent and a fingerprint before publication; do not wait until a whole batch finishes to journal outputs.

Rules for contributors

  • Never call os.remove, shutil.rmtree or os.replace on user files outside actions.py.
  • Engine modules must not import Qt.
  • Every subprocess uses CREATE_NO_WINDOW; every long loop calls progress.update.
  • New user-facing strings follow the writing guidelines in the design document.

Known limitations

  • Blur thresholds and best-shot weights were calibrated on generated images; real libraries may need tuning.
  • Photos is paged, but several analysis/album pages can still load whole groups. Similarity and face-centre merging remain quadratic/dense in their worst cases; preview decoding still runs on the UI thread.
  • RAW previews depend on what Pillow can decode; RAW files are still catalogued and de-duplicated.
  • Network shares are untested; cross-volume moves fall back to verified copy + delete.
  • The packaged app is unsigned (SmartScreen will warn) and ≈340 MB.
  • Video edits always re-encode (frame-accurate, but slower than a lossless stream copy and not bit-identical).
  • The Editor has no layers, text, healing or curves — it is for quick fixes; use a full editor for retouching.
  • Faces are found in photos only, not videos. Profiles, covered faces and faces under ≈20 px may be missed; the same person decades apart, or young children, may form separate groups (join them by name).
  • Place names are the nearest town with 15,000+ people (or the region); small villages are not named.
  • Similar-video matching relies on visual frames; videos with near-identical static content can score close to the threshold.
  • One root per library; multi-folder/offline-drive catalogues remain deferred. Absolute journal paths can complicate Undo after drive-letter changes.
  • Natural Earth boundaries are approximate; map coverage is not authoritative country classification and has no street-level tiles.
  • Reset resumes supported interrupted work but cannot repair physical drive damage or unreadable SQLite storage. Keep backups.
