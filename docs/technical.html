Technical document

How Memoria is built: architecture, modules, data model, algorithms, the journaled executor that makes every change undoable, concurrency, performance, testing and packaging.

Python 3.12PySide6 6.12SQLite (WAL) NumPy · Pillow · OpenCV 4 · FFmpeg 7≈7,600 lines incl. tests

Overview

Memoria is a two-layer application:

  • memoria.engine — a UI-independent library. Every operation is a plain function taking a Library and an optional Progress. It is fully testable without Qt.
  • memoria.ui — a PySide6 shell: a main window with sidebar navigation, one page per tool, a single background TaskRunner, and shared widgets.

All file mutations — from any page — are expressed as a list of Action objects and executed by one function, engine.actions.apply, which journals, verifies and makes them undoable.

Architecture

Dependencies point downward only: pages import engine modules; the engine never imports Qt. The AppContext object carries shared state (open Library, runner, thumbnail cache) and app-wide signals (library_opened, library_modified, toast_requested, navigate).

Pipelines

Indexing (scanner.scan + scanner.analyze)

  1. Walk with an explicit stack over os.scandir, skipping .memoria, $RECYCLE.BIN, System Volume Information; never follows links.
  2. Diff against the catalogue by lower-cased relative path: new rows inserted; rows whose size or mtime changed have derived columns reset (analyzed=0); missing rows removed (with their thumbnails). One transaction.
  3. Analyse un-analysed media in a ThreadPoolExecutor (images: WORKERS threads; videos: a smaller pool). Per image: open → draft() JPEG decode near 512 px → EXIF → transpose → resize to exactly 512 px on the long side → dHash, Laplacian-variance sharpness, brightness, contrast, clipped share → 256 px thumbnail. Per video: probe + one frame at min(1 s, duration/2).
  4. Date resolution: EXIF DateTimeOriginal → DateTimeDigitized → DateTime → video creation_time → regex on file name → file mtime (modified).
  5. Commit every 200 results (catalogue + thumbnails) so cancelled runs keep their progress.

Errors (truncated, unidentified, no video stream) are stored per file and never abort the run.

Exact duplicates (duplicates.confirm_identical)

media files ──group by size──► sizes with ≥2 files ──quick_hash (5×64 KiB + size)──►
groups with equal (size, qhash) ──full_hash (xxh3-128 of whole file)──► identical groups

Hashes are computed in parallel and cached in qhash/chash. The keeper is the minimum of keeper_score = (penalty, mtime, path length, path) where penalty = 3 for a copy-like name ((1), copy, _copy, duplicate, ~1) + 2 for a copy-like folder (backup, download, whatsapp, temp, export…) + 0.1 per folder level. plan_removal emits recycle actions with hash = group hash (forces a fresh full hash of each copy) and a guard = (keeper path, hash) verified once per batch.

Similarity & best shot (similar)

  1. Hash pairs: 64-bit dHashes as uint64; for each 512-row block, XOR against 8,192-column tiles and np.bitwise_count (≈32 MB per tile). Blocks run on a thread pool (NumPy releases the GIL). Pairs with distance ≤ threshold (10) are unioned (disjoint-set).
  2. Bursts: capture times from EXIF/video metadata only (file-name dates are too coarse) are sorted; a sliding window joins pairs ≤ 3 s apart with distance ≤ 16.
  3. Collapse identical: members are passed through confirm_identical; byte-identical files keep one representative (they belong to Duplicates). Groups that fall to one member are dropped.
  4. Faces: computed lazily for group members only (OpenCV Haar, 640 px, thread-local classifier) and cached.
  5. Rank: score = 0.55·log1p(sharp)/log1p(max_sharp) + 0.25·exposure + 0.08·pixels/max_pixels (+ 0.12·faces/max_faces), where exposure = 1 − min(1, 2.5·clipped + 0.6·|brightness−118|/118). Reasons are generated from the same quantities.
  6. Burst flag: ≥3 members, all with capture times, spanning ≤ 3 s × members.

Blurry: sharpness < threshold with presets strict 8 / normal 20 / lenient 45 (variance of the Laplacian at 512 px).

Organise (organize.plan_organize)

Eligible rows: media with a date, no error, size > 0, not AppleDouble. Rows dated only by modified are counted as skipped unless include_uncertain. Destination = pattern folder + original name; clashes with existing or already-planned names (case-insensitive) get " (n)". empty_folders_after walks every source folder's ancestors and returns those whose remaining file count (existing non-moving files + incoming destinations) is zero, deepest first, to append as rmdir actions.

Tidy (tidy.find_tidy)

Classifies catalogue rows: junk (names/extensions/._ prefix) → empty (0 bytes) → unreadable (media with error) → other (non-media). Empty folders are computed from a recursive per-folder count that excludes files about to be removed, so folders containing only junk qualify. Plans recycle files first, then rmdir deepest-first.

Health (health.run_health)

Runs an incremental scan, then re-reads every file (thread pool, half the workers to be gentle on HDDs) computing the full hash and, for images, a reduced-size decode. Classification against the stored fingerprint: none → new; size+mtime equal and hash equal → ok, hash differs → damaged; size or mtime differ → edited; decode failure → unreadable. Fingerprints are refreshed except for damaged files, which stay flagged.

Compare & sync (compare)

Refuses overlapping folders. Lists the other folder without writing to it, then hashes only files whose size occurs on both sides (library hashes cached, other side hashed in memory). Results: only-here, only-there, in-both counts. plan_sync emits copy actions preserving relative paths; the executor's verified copy never overwrites (clashes get a new name).

Video compression (videotools)

  • Output size: limit applied to the shorter side (portrait-safe), even dimensions, Lanczos scaling.
  • Quality mode: libx264 CRF 20 / 24 / 28 (high / balanced / small), preset medium, AAC ≤ 128 kbps (never above the source), -map_metadata 0 -movflags +faststart.
  • Target mode: two-pass ABR; video kbps = target × 97% payload / duration − audio; audio drops to 64 kbps when video would be < 400 kbps; floor 150 kbps (flagged infeasible with an explanation).
  • Progress: -progress pipe:1 parsing of out_time_us; pass 1 = first half.
  • Verification: output must probe, match duration within max(0.5 s, 2%), and be smaller — else discarded. Optional SSIM via FFmpeg's ssim filter over ≤ 600 sampled frames, source scaled to output size.
  • Publishing: work in .memoria-work-* inside the output folder, rename to a unique <stem> (compressed).mp4, copy source mtime. Cancellation kills FFmpeg and removes the work folder.

Estimates (no encoding): quality mode uses bits-per-pixel 0.09 / 0.055 / 0.032 × w × h × fps, capped at 90% of the source video bitrate.

Story rendering (story)

  • Sizes: story 1080×1920, post 1080×1350, square 1080×1080. Photos loaded upright at ≤ 2,200 px.
  • Templates: single, duo, trio, grid4, before_after, polaroid (slots 1/2/3/4/2/1). Backgrounds: blurred darkened cover, black, white or hex colour. Fit: contain, or cover with a centre-weighted edge-energy saliency focus.
  • Captions: Segoe UI fonts, word-wrapped, on a translucent pill with shadow.
  • Panorama carousel: N = round(aspect / 0.8) slides (2–10) cut from one continuous scaled strip, so edges match.
  • Story video: each photo pre-composed once (8% oversize for Ken Burns), per-frame zoom/pan via cv2.warpAffine, crossfades via cv2.addWeighted, raw RGB piped to FFmpeg (libx264 CRF 20, BT.709) by a writer thread with a 4-frame queue. Duration = n·spp − (n−1)·transition. Optional music with a 1 s fade.
  • Exports are all-or-nothing: on cancel, files written in that run are removed.

Action executor & journal

actions.apply(lib, kind, title, actions, progress) is the only code path that changes user files.

for each Action (in order):
    preflight ── guards (keeper exists + full hash, verified once per batch)
              ── src exists / folder empty (rmdir)
              ── size == reviewed size, mtime == reviewed mtime
              ── full_hash(src) == expected (recycle/move with hash)
    fail?  → journal 'skipped' + reason, continue
    dst   = recycle: recovery/<batch>/<rel path>   move/copy: requested path
            made unique ("name (2).ext") — never overwrite
    journal 'pending'
    perform: recycle/move → safe_move (rename on same volume; else verified copy + remove)
             copy         → verified_copy (tmp → hash compare → rename)
             rmdir        → os.rmdir (only if empty)
    journal 'done' | 'failed' + error
update catalogue (remove recycled rows; rewrite moved rel_paths); batch status = applied | partial | nothing

Undo

Processes done operations in reverse. Moves are reversed with safe_move; if the original path is taken the file is restored as a unique name and reported. Copies are removed only if their full hash still equals the recorded source hash. rmdir is reversed with mkdir. The batch becomes undone or partial; empty recovery sub-folders are pruned. The UI re-indexes afterwards.

Crash reconciliation

reconcile(lib) runs whenever a library is opened. For each pending operation it inspects the disk: a move/recycle is done if the destination exists and the source does not; a copy is done if the destination hash matches (stray .memoria-tmp files are removed); otherwise failed. Batches left in applying become partial — and therefore undoable.

Recovery

recovery_size walks the folder; empty_recovery(lib, batch_ids=None) deletes batch folders, marks their recycle operations purged and batches emptied. This is the only deleting function in the codebase.

UI architecture

  • Page lifecycle: pages listen to library_opened/library_modified, mark themselves stale and refresh when visible and the runner is idle (never mid-task). refresh() does cheap catalogue reads; expensive work goes through run().
  • Shared change flow: Page.apply_actions → ConfirmDialog → runner.run(apply [+ index]) → library_modified → toast with Undo (batch id) → failure dialog if needed.
  • PhotoGrid: QListView (icon mode, uniform sizes, batched layout) + PhotoModel holding plain dicts + PhotoDelegate custom painting (rounded thumbnail, badge, tick box, video tag, captions). Thumbnails load on demand through ThumbCache (SQLite BLOB → QPixmap, LRU).
  • Preview: full image decoded at 900 px via media.load_for_display (draft decode keeps it fast).
  • Styling: one Qt stylesheet (theme.QSS) using object names (primary, danger, card, tile, trust…); Fusion style for consistent rendering.
  • Persistence: QSettings("Memoria","Memoria") stores last library, last page and recent libraries.

Techniques

  • JPEG DCT-domain downscaling via Image.draft; Pillow, NumPy and xxhash release the GIL so threads scale.
  • Batched transactions (200 rows), WAL, synchronous=NORMAL, 32 MB page cache, separate thumbnail DB.
  • Size-first duplicate funnel and cached hashes; compare hashes only cross-side size collisions.
  • Tiled, threaded bitwise_count similarity with bounded memory; O(n log n) burst detection.
  • Grid renders only visible cells; pixmaps cached LRU.

Extending Memoria

Adding a tool that changes files

  1. Engine: write a find_* function (read-only, accepts progress) and a plan_* function returning list[Action]. Set size/mtime (and hash/guards when identity matters) so pre-flight can detect stale reviews. Use op="recycle" for removals.
  2. Add ground-truth scenarios to samplelib.build and assertions to tests/test_engine.py, including apply → undo restores the tree.
  3. UI: subclass pages.base.Page, set title/subtitle, implement refresh() and on_busy_changed(), run finds through self.run(), and apply through self.apply_actions(kind, title, actions, summary=…, details=…, confirm_text=…, note=recovery_note(), done_message=…).
  4. Register the page in main_window.NAV and page_classes, add a card to Overview, and extend tools/ui_screenshots.py so the smoke test drives it.

Rules for contributors

  • Never call os.remove, shutil.rmtree or os.replace on user files outside actions.py.
  • Engine modules must not import Qt.
  • Every subprocess uses CREATE_NO_WINDOW; every long loop calls progress.update.
  • New user-facing strings follow the writing guidelines in the design document.

Known limitations

  • Blur thresholds and best-shot weights were calibrated on generated images; real libraries may need tuning.
  • Some pages load the full catalogue into memory on refresh (fine to tens of thousands of files; very large libraries may need pagination).
  • RAW previews depend on what Pillow can decode; RAW files are still catalogued and de-duplicated.
  • Network shares are untested; cross-volume moves fall back to verified copy + delete.
  • The packaged app is unsigned (SmartScreen will warn) and ≈380 MB.
